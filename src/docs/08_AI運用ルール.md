# AI運用ルール

この文書は、AI がこのプロジェクトに対してどのように作業するかを固定するためのルールである。AI は自分の判断で構造や命名を増やしてはいけない。

---

## 1. 参照順序

AI は、作業前に必ず次を確認する。

1. [AI公式情報源マップ.md](../../AI公式情報源マップ.md)
2. [src/content.config.ts](../content.config.ts)
3. 既存の Markdown ファイル
4. 仕様書

情報源の順序を守らない作業は禁止する。

## 2. まず守るべきルール

- 実際の schema を確認してから変更する
- 既存のフィールド名を勝手に変えない
- relatedActivities, references には存在する ID だけを使う
- 新しいコンテンツ名や section 名を作らない
- 政策の主張に根拠がない場合は、追加しない

## 3. AIがしてはいけないこと

- 「良い感じ」だけでコンテンツを増やす
- 仕様書の意味を広げて独自解釈を入れる
- `problem` / `evaluation` / `issues` / `proposals` / `limitations` の役割を変える
- 変更対象と関係ないファイルを勝手に編集する
- schema 変更を伴わずに新しい項目を作る

## 4. 変更の基本形

AI の変更は、必要最小限に限定する。

- Markdown の本文の修正
- 既存構造の値の修正
- 明確なスキーマ変更が必要なときだけ、schema 変更を行う

## 5. 変更後の確認

AI は、修正後に必ず次を行う。

- 対象ファイルが schema に合っているか確認する
- 既存 ID が正しいか確認する
- `npm run build` を実行する
- 変更の影響範囲が大きすぎないか確認する
