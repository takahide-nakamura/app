# AI運用ルール

この文書は、AI がこのプロジェクトを扱うときの作業方法と守るべき原則を定義します。具体的な情報源の整理は [AI公式情報源マップ.md](AI公式情報源マップ.md) へ集約しています。

---

## 1. 基本方針

- 実装・データ・仕様を確認してから変更する
- 推測でスキーマや参照を追加しない
- 変更の影響範囲を最小限にする
- 重要な方針変更は人間に確認する

## 2. 作業の基本流れ

1. [AI公式情報源マップ.md](AI公式情報源マップ.md) を確認する
2. 対象の実装・スキーマ・既存コンテンツを確認する
3. 最小限の変更案を作る
4. 実装し、ビルドで確認する
5. 重要な変更は要約して報告する

## 3. 仕様と実装の優先順位

- 実装上の型は [src/content.config.ts](src/content.config.ts) を優先する
- 仕様書と実装が異なる場合は、両方を確認して矛盾を報告する
- 既存の Content Collection reference がある場合は、存在しない ID を勝手に作らない
