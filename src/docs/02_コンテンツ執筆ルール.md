# コンテンツ執筆ルール

この文書は、政策・活動・出典の文章を、同じ品質で書けるようにするための明示ルールである。文体・構造・記述順を固定し、AI が自由に解釈しすぎないようにする。

---

## 1. 書く対象

このサイトでは、編集対象は次の3種類に限定する。

- policies: 政策ページ
- activities: 活動ページ
- sources: 出典・資料ページ

## 2. 基本文体

- 基本は「です・ます調」
- 1文を長くしすぎない
- 専門用語は必要に応じて説明する
- 断定しすぎず、根拠がある時点で記述する
- 文章の途中で主観と事実を混ぜない

## 3. 政策ページの必須構成

政策本文は、次の順番で書くことを原則とする。

1. problem
2. evaluation
3. issues
4. proposals
5. limitations（必要な場合のみ）
6. 出典参照（sources でまとめる）

この順序を変えて書いてはいけない。各項目は実際のデータ構造と対応させる。

## 4. フロントマターの必須項目

新規政策ファイルでは、次の項目を用いる。

- title
- description
- heroTitle
- heroDescription
- updated
- category
- tags
- relatedActivities
- references
- problem
- evaluation
- issues
- proposals
- limitations

必要な項目がない場合でも、既存の schema に存在しない項目を作ってはいけない。

## 5. 文章の書き方ルール

### 5-1. problem

- 課題の背景・市民の困りごと・現状の説明に使う
- 自分の感想だけではなく、実際の状況が伝わるように書く
- 1段落ごとに内容を分ける

### 5-2. evaluation

- subjective と objective を分けて書く
- subjective は現場や体感に基づく説明
- objective は公的資料や統計に基づく説明
- 両者を同じ文脈で混ぜない

### 5-3. issues

- 課題は title と description を持つ
- 1つの課題は 1つの見出しで書く
- 文章は短く、対策につながる形にする

### 5-4. proposals

- proposal は heading と items を持つ
- 提案は「何を」「どうするか」がわかる形にする
- ただの批判ではなく、改善の方向性を明示する

### 5-5. limitations

- 事実と制約を分けて書く
- 行政だけで解決できない範囲を明示する
- 「どこまでが政策で、どこからが他主体の責任か」を書く

## 6. 活動ページの書き方

活動ページは、次の3点を守る。

- title
- summary
- date
- status
- relatedPolicies（必要な場合）
- thumbnail / photos（必要な場合）
- xUrl / instagramUrl / youtubeUrl（必要な場合）
- 文章は現在の活動内容に関する事実ベースで書く

「何をしたか」「どんな課題があったか」「次にどうつなげるか」を簡潔に書く。

## 7. 出典ページの書き方

source は次の項目を使う。

- title
- publisher
- year
- url

- URL は必ず有効な URL にする
- 出典名と発行主体が明確であること
- 変換や要約で元資料の意味が変わらないようにする

## 8. 禁止事項

- 事実がないのに断定文を入れない
- 既存の各見出しの意味を変えない
- 「いい感じ」の表現で内容を広げない
- 新しい schema を定義して役割を増やさない
