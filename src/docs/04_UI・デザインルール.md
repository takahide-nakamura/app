# UI・デザインルール

この文書は、「もっと住みやすい高槻へ」サイト全体のUI・デザインルールを定義するものです。

目的は、ページごとにデザインや情報構造がばらつかず、市民が迷わず理解できるサイトを維持することです。

---

# 基本思想

デザインは装飾ではありません。

情報を正しく伝えるための手段です。

見た目の格好良さよりも、

- 読みやすい
- 理解しやすい
- 探しやすい

ことを最優先とします。

---

# 3秒ルール

トップページでは、

3秒以内に

- 誰が
- 何を
- なぜ

発信しているサイトなのかが伝わることを目標とします。

---

# ブランドカラー

ブランドカラーは固定します。

- ネイビー（信頼）
- イエロー（行動）
- グレー（補助）

色を増やさないことを原則とします。

---

# フォント

本文は Noto Sans JP を使用します。

フォントは原則変更しません。

---

# レイアウト

3階層読みを基本とします。

見出し

↓

概要

↓

詳細

この構造をすべてのページで統一します。

---

# スマートフォン優先

スマートフォンを基準に設計します。

PC版はその後に最適化します。

---

# アイコン

アイコンは情報構造を示すために使用します。

意味は固定します。

| アイコン | 用途 |
|---------|------|
| 📍 | 問題提起 |
| 👀 | 現場から見えること |
| 📊 | 客観的評価 |
| ⚠️ | 課題抽出 |
| 💡 | 改善の方向性 |
| ✅ | 政策提案 |
| ⛳ | 政策の限界（必要な場合のみ） |
| 📚 | 参考資料 |

アイコンの意味は変更しません。

---

# PolicySection

PolicySectionはページ全体の章を表します。

基本構成は次の順です。

1. 問題提起
2. 評価
3. 課題抽出
4. 政策提案
5. 政策の限界（必要な場合）
6. 参考資料

章を増やしすぎないことを原則とします。

---

# EvidenceBox

EvidenceBoxは「評価」を整理するためのコンポーネントです。

使用する種類は3種類に固定します。

- 📊 客観的評価
- ⚠️ 課題抽出
- 💡 改善の方向性

EvidenceBoxは章ではありません。

評価の中を整理する部品として使用します。

---

# ProposalList

政策提案は ProposalList を使用します。

「私の提案」と「この政策で目指すこと」は同じ「政策提案」の章で扱います。

---

# RelatedActivities

活動ページとの関連付けを行う場合に使用します。

政策と活動を相互に結び付けることを目的とします。

---

# ReferenceList

参考資料はページの最後に配置します。

途中へ配置しません。

---

# 余白

情報量よりも読みやすさを優先します。

余白もデザインの一部です。

---

# デザイン変更

デザインは目的がある場合のみ変更します。

見た目だけを理由に変更しません。

UI・デザインの変更は、設計原則との整合性を確認した上で行います。
