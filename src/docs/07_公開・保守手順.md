# 公開・保守手順

この文書は、サイト公開から日常運営までの基本手順、および非エンジニアが安全に政策ページや参考文献を新規追加・管理するための手順を定めます。

---

# 基本方針

「壊さない」

「慌てない」

「記録を残す」

を原則とします。

# 政策ページ（Policies）の作成・追加手順

新しい政策ページを追加するときは、以下の手順とルールを必ず守ってください。

### 1. ファイルの作成場所とファイル名（名付けの法則）
- **作成場所**: `src/content/policies/`
- **名付けの法則**: **半角の英小文字、数字、ハイフン（`-`）**のみを使用します。
  - **よい例**: `care-certification.md`, `dementia-support.md`, `garbage-problem.md`
  - **悪い例**: `CareCertification.md`（大文字混ざり）, `dementia_support.md`（アンダースコア）, `介護保険.md`（日本語）

### 2. ファイルの書き方とテンプレート
ファイルの一番上に、`---`（半角ハイフン3つ）で囲まれた設定情報を記述します。この部分を「フロントマター」と呼びます。

**実例テンプレート（コピペしてお使いください）**:
```markdown
---
title: "要介護認定"
description: "必要な人が必要な介護サービスを適切な時期に利用できるよう、要介護認定制度の改善を提案します。"
heroTitle: "要介護認定"
heroDescription: "必要な人が、必要な介護サービスを適切な時期に受けられる仕組みを目指します。"
updated: "2026-08-01"
category: "🏥 医療・介護"
tags: ["要介護認定", "介護保険", "介護", "高齢者"]

# 関連する活動実績のID（src/content/activities/ 配下にあるmdファイルのファイル名。ない場合は空にするか項目ごと削除可）
relatedActivities:
  - nursing-care-visit

# 参考文献のID（src/content/sources/ 配下にあるmdファイルのファイル名。後述）
references:
  - takatsuki-audit-2025

# 課題・現状分析
problem:
  paragraphs:
    - "介護サービスを利用するためには、要介護認定を受ける必要があります。"
    - "しかし、認定まで時間がかかったり、制度が分かりにくかったりすることで、不安を抱える方が少なくありません。"

# 評価・分析
evaluation:
  subjective:
    heading: "現場で感じること"
    paragraphs:
      - "理学療法士として現場に関わる中で、結果が出るまでの期間に不安を抱えるご家族を多く見てきました。"
  objective:
    heading: "公的資料から分かること"
    paragraphs:
      - "高槻市でも高齢化に伴い、認定を必要とする方は今後さらに増加すると見込まれています。"

# 課題
issues:
  - title: "認定までの期間に不安を抱えやすい"
    description: "申請から認定結果が出るまで一定の期間が必要となるため、その間に不安を感じる方がいます。"

# 政策提案
proposals:
  - heading: "今すぐ取り組めること"
    items:
      - "要介護認定の流れを分かりやすく周知します。"
  - heading: "高槻市として取り組むこと"
    items:
      - "認定調査からサービス利用までの相談支援を充実させます。"

# 限界点・前提条件
limitations:
  paragraphs:
    - "要介護認定制度は介護保険法に基づく全国共通の制度であり、高槻市だけで認定基準を直接変更することはできません。"
---
```

# 参考文献（Sources）の作成・追加手順

政策ページに紐づける参考文献（データソース）を登録する手順です。

### 1. ファイルの作成場所とファイル名（名付けの法則）
- **作成場所**: `src/content/sources/`
- **名付けの法則**: **半角の英小文字、数字、ハイフン（`-`）**のみを使用します。
  - **よい例**: `takatsuki-audit-2025.md`, `dementia-plan-2024.md`, `who-noise.md`
  - **悪い例**: `takatsukiAudit2025.md`（大文字混ざり）, `takatsuki_audit.md`（アンダースコア）

### 2. ファイルの書き方とテンプレート
参考文献用のファイルも、先頭に `---` で囲まれた設定情報を書きます。

**実例テンプレート（コピペしてお使いください）**:
```markdown
---
title: "令和7年度 高槻市包括外部監査結果報告書（高齢者福祉事業及び介護保険事業に関する財務事務の執行について）"
publisher: "高槻市"
year: "2025"
url: "https://www.city.takatsuki.osaka.jp/uploaded/attachment/63214.pdf"
---

WHOが公表しているガイドラインです。（←ここには簡単な説明やメモを日本語で自由に記述できます。空欄でも問題ありません）
```
> **注意点**:
> - `url` は必ず `http://` または `https://` から始まる有効なWebアドレスを記述してください。
> - `year`（発行年）がわからない場合は、空欄 `""` にしてください。（例: `year: ""`）

### 3. 政策ページと参考文献を結びつける（関連付け）
1. `src/content/sources/` に新しい参考文献ファイルを作成します（例: `takatsuki-audit-2025.md`）。
2. 対象の政策ページファイル（例: `src/content/policies/care-certification.md`）を開きます。
3. フロントマターの `references:` リストの中に、作成した参考文献の **ファイル名（`.md` を除いた部分）** を半角ハイフンの後ろに指定します。
   ```yaml
   references:
     - takatsuki-audit-2025
   ```

# 更新手順

日常的なサイトの更新は、以下の手順に沿って安全に行ってください。

① 内容を修正（ページ作成、テキスト修正など）

↓

② ローカル確認（パソコン上の表示に崩れがないか確認）

↓

③ エラー確認（コンソールやプレビュー画面にエラーが出ていないか確認）

↓

④ コミット（Gitに変更を記録）

↓

⑤ GitHubへPush（サーバーにデータを送信）

↓

⑥ 公開確認

---

# コミット

変更内容が分かるコミットメッセージを使用します。

例

Update noise policy

Fix typo

Add garbage policy

---

# 公開確認

Push後に実際のホームページで正しく表示されているか確認します。

- トップページ
- 政策一覧
- 更新ページ
- リンク切れ
- スマホ表示

---

# エラー対応

エラーが発生した場合は

エラーメッセージ全文

発生箇所

変更した内容

を確認します。

推測で修正しません。

---

# バックアップ

GitHubを正本とします。

ローカルだけを正本にしません。

---

# 更新頻度

活動報告は随時更新します。

政策ページは内容に変更がある場合のみ更新します。

---

# 定期確認

月1回を目安に確認します。

- リンク切れ
- 古い情報
- 参考資料
- スマホ表示

---

# AIとの運用

コード編集前には設計書を確認します。

設計変更が必要な場合は

設計書

↓

コード

の順番で更新します。

---

# 原則

設計書が最上位です。

コードは設計書に従います。

運用中に新しいルールが必要になった場合は

設計書を更新してからコードを修正します。
