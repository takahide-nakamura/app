# 公開・保守手順マニュアル

この文書は、サイト公開から日常運営までの基本手順、および非エンジニアが安全に活動コンテンツ、政策ページ、参考文献を新規追加・編集・公開・管理するための手順を定めます。

---

## 1. 基本方針

本サイトの運用管理は、以下の原則と運用規約に基づいて行います。

### 1-1. 3つの運用原則
- **壊さない**: 変更前に対象ファイルと設計を確認し、意図しない破壊を防ぎます。
- **慌てない**: エラーやトラブルが発生しても推測で修正せず、原因を切り分けて対処します。
- **記録を残す**: 誰が・いつ・何を変更したかをGit/GitHub上に明確に記録します。

### 1-2. 設計書とコードの優先順位（AIとの運用方針）
- **設計書が最上位**: コードは設計書に従います。
- **変更手順**: 設計変更が必要になった場合は、必ず **「設計書を更新」→「コード・コンテンツを修正」** の順番で対応します。
- コード編集前には設計書を必ず確認し、独断や推測での変更を行いません。

### 1-3. バックアップと正本管理
- **GitHubを正本とする**: ローカルPC内のファイルだけを正本とはせず、必ずPushしてGitHub上に最新の正本を保持します。

---

## 2. コンテンツ管理の基本ルール（共通）

本サイトのコンテンツ（活動報告・政策・参考文献）はすべて Markdown (`.md`) ファイルで管理されています。

### 2-1. 管理場所一覧
| コンテンツ種別 | ディレクトリパス | 用途 |
| :--- | :--- | :--- |
| **活動（Activities）** | `src/content/activities/` | 活動実績、訪問記録、イベント報告など |
| **政策（Policies）** | `src/content/policies/` | 政策提案、課題分析、現状評価など |
| **参考文献（Sources）** | `src/content/sources/` | 政策等の根拠となる公的資料・論拠データ |

### 2-2. ファイル名のルール（Kebab-case）
すべてのファイル名は以下の規則を厳格に守ってください。ファイル名はURLや内部参照の識別子（ID）として使われます。

- **使用可能**: 半角英小文字、半角数字、ハイフン（`-`）
- **使用不可**: 大文字、アンダースコア（`_`）、全角文字、日本語、スペース

- **良い例**:
  - `nursing-care-visit.md`
  - `care-certification.md`
  - `takatsuki-audit-2025.md`
- **悪い例**:
  - `NursingCareVisit.md`（大文字混ざり）
  - `dementia_support.md`（アンダースコア使用）
  - `介護訪問.md` / `要介護認定.md`（日本語使用）

## 3. 活動コンテンツ（Activities）の管理手順

活動一覧および詳細ページで表示されるコンテンツの追加・編集手順です。

### 3-1. フロントマターと書き方
ファイル先頭に `---`（半角ハイフン3つ）で囲まれたメタデータを記述します。

**テンプレート（コピペ用）**:
```markdown
---
title: "介護現場の訪問"
summary: "現場で働く皆さまから、介護保険制度や人材不足についてお話を伺いました。"
updated: "2026-08-04"
status: "published"
---

ここに本文を記述します。

複数段落に分け、事実と現場の声を中心に分かりやすく記載してください。
```

**フロントマターの項目説明**:
- `title`: 活動名。一覧カードや見出しに使用（短く分かりやすく）。
- `summary`: 一覧表示用の要約（1〜2文程度）。
- `updated`: 更新日（形式: `YYYY-MM-DD`）。
- `status`: 公開状態コントロール。
  - `published`: サイト上に公開
  - `draft`: 下書き状態（一覧に非表示）

### 3-2. 新規追加手順
1. `src/content/activities/` に新しい `.md` ファイルを作成する（例: `disaster-prevention-meeting.md`）。
2. 上記テンプレートを貼り付け、フロントマターの各項目（`title`, `summary`, `updated`, `status`）を設定する。
3. `---` の下に本文を記述して保存する。
4. 後述の「ローカル確認」を行い、表示に問題がなければコミット・Pushする。

### 3-3. 更新手順
1. 対象の `.md` ファイルを開く。
2. 内容の変更に合わせて `title`, `summary`, 本文を修正する。
3. `updated`（更新日）を修正当日の日付に変更する。
4. 一覧用の `summary` と本文の内容に食い違いがないか確認して保存する。

### 3-4. 非公開化と削除の手順
- **一時的な非公開**: フロントマターの `status` を `"draft"` に変更します。ファイルは残りますがサイト上には表示されなくなります。
- **完全削除**: 対象の `.md` ファイル自体を削除します。削除後は関連ページにリンク切れ等の崩れがないか必ず確認してください。

## 4. 政策ページ（Policies）の管理手順

政策提案や課題分析を表示するページです。構造化された詳細なフロントマターを使用します。

### 4-1. フロントマターと書き方
政策ページはフロントマター内に詳細なデータ構造を記述します。

**テンプレート（コピペ用）**:
```markdown
---
title: "要介護認定"
description: "必要な人が必要な介護サービスを適切な時期に利用できるよう、要介護認定制度の改善を提案します。"
heroTitle: "要介護認定"
heroDescription: "必要な人が、必要な介護サービスを適切な時期に受けられる仕組みを目指します。"
updated: "2026-08-01"
category: "🏥 医療・介護"
tags: ["要介護認定", "介護保険", "介護", "高齢者"]

# 関連する活動実績のID（src/content/activities/ のファイル名・拡張子なし。ない場合は [] または空）
relatedActivities:
  - nursing-care-visit

# 参考文献のID（src/content/sources/ のファイル名・拡張子なし）
references:
  - takatsuki-audit-2025

# 課題・現状分析
problem:
  paragraphs:
    - "介護サービスを利用するためには、要介護認定を受ける必要があります。"
    - "しかし、認定まで時間がかかったり、制度が分かりにくかったりすることで、不安を抱える方が少なくありません。"

# 評価・分析
evaluation:
  subjective:
    heading: "現場で感じること"
    paragraphs:
      - "理学療法士として現場に関わる中で、結果が出るまでの期間に不安を抱えるご家族を多く見てきました。"
  objective:
    heading: "公的資料から分かること"
    paragraphs:
      - "高槻市でも高齢化に伴い、認定を必要とする方は今後さらに増加すると見込まれています。"

# 課題
issues:
  - title: "認定までの期間に不安を抱えやすい"
    description: "申請から認定結果が出るまで一定の期間が必要となるため、その間に不安を感じる方がいます。"

# 政策提案
proposals:
  - heading: "今すぐ取り組めること"
    items:
      - "要介護認定の流れを分かりやすく周知します。"
  - heading: "高槻市として取り組むこと"
    items:
      - "認定調査からサービス利用までの相談支援を充実させます。"

# 限界点・前提条件
limitations:
  paragraphs:
    - "要介護認定制度は介護保険法に基づく全国共通の制度であり、高槻市だけで認定基準を直接変更することはできません。"
---
```

### 4-2. 関連コンテンツとの紐づけ方法
- 関連活動の紐づけ: relatedActivities: の配下に、対象となる活動ファイル名（.md 除く）を指定します。
- 参考文献の紐づけ: references: の配下に、対象となる参考文献ファイル名（.md 除く）を指定します。
- YouTube動画の紐づけ: youtube: に、その政策を解説するYouTube動画のタイトルとURLを指定します。
- YouTube動画が存在しない政策では、youtube: 自体を記載しません。
- SNS投稿については、現時点では政策Markdownに投稿URLを登録せず、各SNSの投稿から直接対応する政策ページへリンクします。

#### YouTubeの記述例
youtube:
  title: "認知症について解説"
  url: "https://www.youtube.com/watch?v=LYzGvcYkf7E"
YouTubeを設定しない政策
#### youtube: は記載しない

YouTube情報を登録していない政策では、政策ページにYouTubeへのリンクは表示されません。

### 4-3. 新規追加・更新手順
1. src/content/policies/ 内に対象ファイルを作成・編集します。
2. フロントマターの各項目（タイトル、説明、課題、分析、提案等）を記述します。
3. 関連活動・参考文献のIDが正しく指定されているか確認します。
4. 対応するYouTube動画がある場合は、youtube.title と youtube.url を追加します。
5. YouTube動画がない場合は、youtube: を記載しません。
6. 保存後、npm run build を実行してエラーがないことを確認します。
7. ブラウザで政策ページを確認し、YouTubeリンクが正しく表示されることを確認します。
8. 問題がなければGitにコミットし、GitHubへPushします。

## 5. 参考文献（Sources）の管理手順

政策ページの根拠となる公的資料やデータソースを管理する手順です。

### 5-1. フロントマターと書き方
**テンプレート（コピペ用）**:
```markdown
---
title: "令和7年度 高槻市包括外部監査結果報告書（高齢者福祉事業及び介護保険事業に関する財務事務の執行について）"
publisher: "高槻市"
year: "2025"
url: "https://www.city.takatsuki.osaka.jp/uploaded/attachment/63214.pdf"
---

ここに簡単な説明や補足メモ（日本語）を記述できます（空欄でも可）。
```

**記述上の注意点**:
- `url`: 必ず `http://` または `https://` から始まる有効なURLを記載します。
- `year`: 発行年（不明な場合は空文字 `""` とする）。

### 5-2. 政策ページと参考文献の紐づけ作業順序
1. `src/content/sources/` に参考文献ファイル（例: `takatsuki-audit-2025.md`）を作成・保存する。
2. 紐づけたい政策ファイル（例: `src/content/policies/care-certification.md`）を開く。
3. 政策ファイルの `references:` に参考文献のID（拡張子無しのファイル名）を追加する。
   ```yaml
   references:
     - takatsuki-audit-2025
   ```

## 6. ローカル確認とビルド検証

変更を行った後、いきなり公開せず必ず自分のパソコン上で表示および動作を確認します。

### 6-1. 確認用コマンド
ターミナル（コマンドプロンプト等）でプロジェクト直下に移動し、以下を実行します。

```bash
# 開発サーバーの起動（ローカルでの表示確認）
npm run dev
```
起動後、表示されるURL（例: `http://localhost:4321`）にブラウザでアクセスして確認します。

```bash
# ビルドテスト（エラーなく静的ファイルが生成されるか確認）
npm run build
```
公開前の最終確認として、ビルドエラーが発生しないかテストできます。

### 6-2. 表示確認のチェックリスト
- [ ] **トップページ**: 表示崩れがないか
- [ ] **活動一覧・詳細**: 新規カード・本文・更新日が正しく反映されているか（`draft`が非表示になっているか）
- [ ] **政策一覧・詳細**: 課題・評価・提案が綺麗に整形され、関連活動・参考文献リンクが動作しているか
- [ ] **参考文献一覧**: タイトル・発行元・外部リンクURLが正常か
- [ ] **リンク切れ確認**: 設置した内部・外部リンクが正しくつながるか
- [ ] **スマートフォン表示**: スマホ幅の画面サイズで文字化けやレイアウト崩れがないか
- [ ] **YouTube連携**: 政策ページからYouTube動画を開けるか
- [ ] **SNS連携**: SNSから対応する政策ページへ正しく移動できるか
- [ ] **外部リンク**: YouTube・SNS等の外部リンクが正常か

---

## 7. 公開フロー（Git / GitHub 運用）

ローカル確認で問題がないことを確認したら、以下の順序で公開作業を進めます。

### 7-1. 全体フロー
```
① 内容修正・作成（Markdown編集）
  ↓
② ローカル確認（npm run dev で表示・レイアウト確認）
  ↓
③ エラー確認（コンソール・ターミナルエラーが無いか確認）
  ↓
④ コミット（Gitに変更内容を記録）
  ↓
⑤ GitHubへPush（リポジトリへ送信・自動公開処理実行）
  ↓
⑥ 本番環境での公開確認
```

### 7-2. コミットメッセージのルール
変更内容が一目でわかるように簡潔に記述します。

**良い例**:
- `Add new activity: disaster-prevention-meeting`
- `Update care-certification policy content`
- `Fix typo in takatsuki-audit-2025 source`
- `Publish new policy: dementia-support`

## 8. エラー対応・定期保守・運用ルール

### 8-1. エラー発生時の対処方法
エラーが発生した場合は、**決して推測で修正せず**、以下の3点を確認して切り分けを行います。

1. **エラーメッセージ全文**: 何が原因と表示されているか
2. **発生箇所**: どのファイルの何行目か
3. **直前に変更した内容**: どの記述を追加・変更したか

疑問や不具合がある場合は、既存の正常に動いている Markdown ファイルの記述構造と比較してください。

### 8-2. 定期保守（月1回を目安）
定期的にサイト全体の健全性を確認します。

- リンク切れの有無（外部URLの変更・消失確認）
- 情報の鮮度（古い日付や陳腐化した情報の見直し）
- 参考文献の更新有無
- スマホ・PCでの表示確認

### 8-3. コンテンツの更新頻度目安
- **活動報告（Activities）**: 随時更新（活動後速やかに追加）
- **政策ページ（Policies）**: 内容や前提条件に変更が生じた場合に適宜更新

# 9. SNS・YouTube連携の運用ルール

本章では、政策ページとYouTube、X、Instagram、note等のSNSを連携させる際の基本ルールを定めます。

## 9-1. 基本方針

SNS・YouTubeは、政策ページとは別の情報源ではなく、**政策を分かりやすく伝えるための発信経路**として扱います。

情報の中心となるのは、サイト上の政策ページです。

基本的な関係は以下のとおりです。

```
                 YouTube
                ↗       ↘
               /         \
              ↓           ↓
SNS ───────→ 政策ページ
              ↑
              │
          公式サイト
```

原則として、

**政策ページ = 詳細な情報・根拠・政策提案を確認する場所**

**YouTube = 政策の背景や考え方を動画で理解する場所**

**SNS = 政策や活動を短く知り、政策ページへ誘導する場所**

として役割を分けます。

---

## 9-2. 政策ページを情報の基準点とする

政策に関する発信では、政策ページを情報の基準点とします。

例えば「認知症支援」について発信する場合、

```
政策ページ
/policy/dementia-support/
        ↓
YouTube
認知症について解説
        ↓
X・Instagram・note
認知症に関する投稿
```

という関係にします。

SNSやYouTubeの内容を政策ページと大きく異なるものにしないでください。

特に以下については注意します。

- 数字
- 制度の説明
- 法律・制度上の事実
- 公的資料の内容
- 政策提案の内容
- 現在の制度と将来の提案の区別

変更があった場合は、まず政策ページの内容を確認・更新し、その後SNSやYouTube側の情報との整合性を確認します。

---

## 9-3. 政策ページ → YouTube

対応するYouTube動画がある政策では、政策ページからYouTubeへリンクします。

政策Markdownには以下の形式で登録します。

```yaml
youtube:
  title: "認知症について解説"
  url: "https://www.youtube.com/watch?v=LYzGvcYkf7E"
```

これにより、政策ページに、

```
🎥 この政策を動画で解説

認知症について解説

[YouTubeで見る]
```

が表示されます。

### 運用ルール

- YouTube動画が実際に公開されていることを確認してから登録します。
- URLは実際のYouTube動画URLを使用します。
- URLを推測して入力しません。
- 動画を削除・非公開にした場合は、政策ページ側のYouTubeリンクも確認します。
- 動画の内容が政策ページの内容と大きく異なる場合は、リンクを登録する前に内容を確認します。

---

## 9-4. YouTube → 政策ページ

YouTube動画からも、対応する政策ページへ誘導します。

動画の概要欄には、原則として以下の形式で政策ページへのリンクを掲載します。

```
この動画で解説している政策の詳しい内容はこちら
▼
【認知症支援】
https://公開サイトのURL/policy/dementia-support/
```

### 運用ルール

- 動画に対応する政策ページがある場合は、概要欄から政策ページへリンクします。
- ローカル環境のURL（`localhost`）は絶対に記載しません。
- 公開済みの本番URLを使用します。
- 動画を公開した後、概要欄の政策ページリンクが正常に開くことを確認します。

---

## 9-5. SNS → 政策ページ

X、Instagram、note等で政策について発信する場合は、可能な限り対応する政策ページへ直接誘導します。

基本形は以下です。

```
政策について詳しくはこちら
▼
【認知症支援】
https://公開サイトのURL/policy/dementia-support/
```

SNSからは、原則としてトップページではなく、**その投稿に対応する政策ページへ直接リンクします。**

### 良い導線

```
X
 ↓
認知症についての投稿
 ↓
認知症支援政策ページ
```

### 避ける導線

```
X
 ↓
トップページ
 ↓
政策
 ↓
認知症支援
```

SNS利用者に追加の検索・操作を要求せず、目的の情報へ直接移動できるようにします。

---

## 9-6. 政策ページ → SNS

現段階では、政策ページから個別のX投稿・Instagram投稿・note記事を自動的に管理する仕組みは導入しません。

理由は、SNS投稿URLが投稿ごとに異なり、SNS運用開始前に管理項目を増やす必要がないためです。

現在の `src/data/socials.ts` は、以下のような**公式SNSアカウントへのリンクを管理するために使用します。**

```tsx
export const socials = {
  youtube: {
    name: "YouTube",
    url: "",
  },

  x: {
    name: "X",
    url: "",
  },

  instagram: {
    name: "Instagram",
    url: "",
  },

  note: {
    name: "note",
    url: "",
  },
};
```

ここに登録するURLは、個別投稿URLではなく、原則として各SNSの公式アカウントURLとします。

### 例

```
YouTube → YouTubeチャンネル
X → X公式アカウント
Instagram → Instagram公式アカウント
note → note公式アカウント
```

個別の政策投稿URLは `socials.ts` には登録しません。

---

## 9-7. SNS・YouTube投稿を作成する順序

政策に関する発信を行う場合は、以下の順序を基本とします。

```
① 政策ページの内容を確認
        ↓
② 必要なら政策ページを更新
        ↓
③ YouTube動画を作成・公開
        ↓
④ YouTube概要欄に政策ページURLを掲載
        ↓
⑤ 政策MarkdownにYouTube URLを登録
        ↓
⑥ SNS投稿を作成
        ↓
⑦ SNS投稿から政策ページへリンク
        ↓
⑧ サイトをローカル確認
        ↓
⑨ npm run build
        ↓
⑩ Git commit
        ↓
⑪ GitHubへPush
        ↓
⑫ 公開後に本番サイトを確認
```

ただし、YouTube動画を作成しない場合は、③〜⑤を省略します。

## 9-10. SNS・YouTubeと政策ページの更新が必要になった場合

政策内容を変更した場合は、SNSやYouTubeの過去の発信内容との整合性を確認します。

特に以下の変更では注意が必要です。

- 制度変更
- 法律変更
- 数字・統計の更新
- 政策提案の変更
- 政策の撤回・修正
- 参考資料の更新
- YouTube動画の内容と現在の政策の相違

政策ページを更新しただけで、過去のSNS投稿やYouTube動画まで自動的に更新されるわけではありません。

そのため、重要な変更がある場合は、

```
政策ページ更新
    ↓
過去のYouTube動画を確認
    ↓
過去のSNS投稿を確認
    ↓
必要なら概要欄・投稿内容を修正
```

という確認を行います。

## 9-12. SNS・YouTube連携の基本原則

本サイトでは、以下の原則を維持します。

### 原則1：政策ページを情報の基準点にする

SNSやYouTubeだけで政策の全体像を説明するのではなく、詳細な情報・根拠・政策提案は政策ページに集約します。

### 原則2：SNSは入口にする

SNSではすべてを説明しようとせず、興味を持った人が政策ページへ移動できる導線を用意します。

### 原則3：YouTubeは理解を深める入口にする

動画では文章だけでは伝わりにくい背景、考え方、現場経験などを伝え、必要に応じて政策ページへ誘導します。

### 原則4：一つの政策に一つの基準URLを持つ

例えば認知症支援なら、

```
/policy/dementia-support/
```

を基本の政策URLとして使用します。

SNSやYouTubeごとに別の政策ページを作りません。

### 原則5：リンクは直接目的地へ送る

SNSからトップページを経由させるのではなく、関連する政策ページへ直接リンクします。

### 原則6：リンクを増やしすぎない

すべてのページにすべてのSNSリンクを配置するのではなく、利用者が次に取るべき行動を考えて必要なリンクだけを設置します。
