# 公開・保守手順

この文書は、更新作業の最小手順を定義する。非エンジニアでも使えるよう、Markdown を編集する前提で整理する。

---

## 1. 変更前の確認

編集前に、次を確認する。

1. 対象ファイルがどこにあるか
2. 何を更新したいか
3. 既存の構造を壊さないか
4. 参考資料や関連活動の ID が存在するか
5. 更新日を変える必要があるか

## 2. 更新対象の場所

- 政策: [src/content/policies](../content/policies)
- 活動: [src/content/activities](../content/activities)
- 出典: [src/content/sources](../content/sources)
- スキーマ: [src/content.config.ts](../content.config.ts)
- 表示: [src/components](../components) と [src/pages](../pages)

## 3. 更新時の手順

### 3-1. 政策を更新するとき

- title, description, heroTitle を確認する
- problem, evaluation, issues, proposals を必要に応じて修正する
- references が既存の sources ID と一致しているか確認する
- updated を最新日付に更新する

### 3-2. 活動を更新するとき

- title, summary, updated, status を確認する
- 本文は事実に基づいて書く
- 既存の status が published / draft のどちらかであることを守る

### 3-3. 出典を更新するとき

- title, publisher, year, url を確認する
- URL を間違えない
- year が不明なら空欄を許容するが、必ず正確な情報にする

## 4. 変更後に確認すること

編集後は、次を確認する。

- フロントマターの書式が崩れていないか
- 関連する ID が存在するか
- 政策本文の流れが problem → evaluation → issues → proposals になっているか
- 参考資料と関連活動が終わりにまとめられているか
- `npm run build` が成功するか

## 5. 禁止事項

- 既存の schema を勝手に変える
- 新しいフィールドを勝手に追加する
- 参照先が存在しない ID を使う
- 変更をまとめずに大きな編集を行う
