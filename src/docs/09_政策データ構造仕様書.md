# 政策データ構造仕様書

この文書は、現行実装で使っている Content Collection の正式な構造と、編集時に守るべきルールを定義する。実装の厳密な定義は [src/content.config.ts](../content.config.ts) を正とする。

---

## 1. Collection の役割

### policies

政策本文・評価・提案・出典の関係を管理する。

### activities

活動の要約と公開状態を管理する。

### sources

資料のメタデータを管理する。

---

## 2. Policy の必須構造

Policy は次のフィールドを持つ。

- title: string
- description: string
- heroTitle: string
- heroDescription: string | undefined
- category: enum | undefined
- tags: string[]
- updated: YYYY-MM-DD | undefined
- relatedActivities: reference("activities")[]
- references: reference("sources")[]
- youtube: { title: string, url: string } | undefined
- problem: { paragraphs: string[] } | undefined
- evaluation: { subjective?: { heading: string, paragraphs: string[] }, objective?: { heading: string, paragraphs: string[] } } | undefined
- issues: { title: string, description: string }[] | undefined
- proposals: { heading: string, items: string[] }[] | undefined
- limitations: { paragraphs: string[] } | undefined

### ルール

- フィールド追加は原則禁止
- 必須項目が欠けている場合は編集時に補う
- relatedActivities と references は、実在する ID のみ使う
- problem, evaluation, issues, proposals, limitations は、定義された意味を変えない

---

## 3. Activity の必須構造

Activity は次のフィールドを持つ。

- title: string
- summary: string
- updated: YYYY-MM-DD
- status: "published" | "draft"

### ルール

- status は published または draft のどちらかのみ
- updated は必ず YYYY-MM-DD 形式
- summary は短い説明にする

---

## 4. Source の必須構造

Source は次のフィールドを持つ。

- title: string
- publisher: string
- year: string | undefined
- url: string

### ルール

- title と publisher は必須
- url は有効な URL であること
- year が不明なときは空欄にできるが、資料の発行元とタイトルは明確にする

---

## 5. 禁止事項

次の変更は行わない。

- 既存のフィールド名の変更
- 既存のフィールドの意味の変更
- 参照先の ID を推測で作る
- 「良い感じ」の新しい見出しを増やす
- 実装と一致しない文書の書き換え

---

## 6. 変更時の確認順

データ構造を変更する場合は、次の順で確認する。

1. [src/content.config.ts](../content.config.ts) を確認する
2. 既存の content ファイルを確認する
3. 参照関係を確認する
4. 実装側とドキュメントを揃える
5. `npm run build` を実行する
